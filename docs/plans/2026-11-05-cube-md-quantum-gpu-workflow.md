# cube：从 MD 单帧到 dimer、QM/MM 参数和 GPU KMC

2026-11-05，讨论中的需求与建议设计。**以下是目标工作流，不表示相关功能已经实现或通过 GPU 数值测试。** 本轮用户补充的要求优先于此前“先导入已有电子参数”的实现顺序。

## 1. 用户已经明确的目标

1. 输入 MD 的某一帧结构，同时适合 GROMACS 和 LAMMPS。
2. 用户指定每个分子中的原子编号，例如 1–5 号组成共轭平面，按不同分子的这些共轭区域之间的距离筛选 dimer。
3. 提取 dimer 后计算电子耦合/转移积分。
4. 在 QM/MM 环境下计算重组能。
5. GPU 用于**量化计算和 KMC**。这是最新确认的范围，取代此前仅加速量化的表述。
6. 最终贯通电子参数→速率→载流子输运→迁移率及收敛报告；保留既定四语言核心与 Python＋uv 工作流。
7. 用户已确定首个 GPU QM/MM 重组能验证案例：**固定周围分子，只优化 QM 分子**。这一选择确定验证先后，不取消环境可松弛模式的扩展位置。
8. 用户已确定 KMC 首版先验证**独立单载流子轨迹**；有限浓度与相互作用模型保留扩展位置。

用户已说明筛选区域是共轭平面，不应将其解释为随意选择的原子对。当前待明确的是“区域间距离”的数学定义。已向用户列出三种可选规则：最短所选原子距离、所选原子质心距离、拟合层间距加倾角/横向错位。不能静默将三者互换。

## 2. 端到端目标

```text
GROMACS / LAMMPS 的结构帧与拓扑/力场
  → 原子、分子和电子活性片段映射；PBC 还原
  → 按所选共轭区域筛选分子对与周期镜像
  → 提取完整 dimer + 一致的周围 MM 环境
  → dimer 转移积分任务 / 位点 QM/MM 重组能任务
  → 带来源的 V、λ、位点能与质量检查
  → 定向速率网络
  → CPU 四语言后端 / GPU KMC
  → 扩散、漂移、迁移率与统计/形貌收敛报告
```

“从一帧结构开始”是用户入口；QM/MM 仍需要拓扑、元素/原子类型、电荷与适用的力场参数。坐标文件本身不足以唯一确定这些物理量，缺失信息应清晰指出。

## 3. GROMACS 与 LAMMPS 输入适配器

| 输入 | 几何和映射 | QM/MM 额外要求 |
|---|---|---|
| GROMACS | GRO 单帧，或轨迹中的指定帧；结合 TPR/拓扑恢复分子、元素、键和电荷 | TOP/ITP、include 文件与力场；TPR 读到的电荷不等于已经导入全部 MM 相互作用参数 |
| LAMMPS | data＋指定 dump 帧；保留原始 atom ID、molecule ID、类型、盒子/倾斜量和 image 标志 | atom_style、units、type→element 映射、charges、pair/bond 等样式和系数；部分信息在输入脚本/include 中，不能只靠 dump 猜测 |

建议统一成 cube 的 Atom/Molecule/Cell 模型后再做提取。可以复用 [MDAnalysis 的 LAMMPS 解析](https://docs.mdanalysis.org/stable/documentation_pages/topology/LAMMPSParser.html)和 [TPR 解析](https://docs.mdanalysis.org/stable/documentation_pages/topology/TPRParser.html)能力，但适配器负责校验信息是否真实存在。原子类型不总能唯一推断元素；不把推测的质量/元素/电荷当作已知参数。

LAMMPS dump 行顺序可以变化，应按 atom ID 对齐拓扑，不按文件行号对齐。GRO 的编号/残基字段可能回绕，稳定身份应来自完整映射而非只用显示编号。规范层统一单位；保留原始编号与转换记录。

## 4. 共轭区域筛选与完整 dimer 提取

### 编号与区域

用户举例“分子中 1–5 号”可自然表达为**分子局部编号、1-based**。配置需显式记录 index_scope/index_base；也支持全局 atom ID 和按分子类型的不同选择，不能默认每种分子拥有相同原子顺序。

共轭选择用于几何判据。通过判据后默认输出两个完整分子及其实际相对位置。若将来需要只输出共轭片段，必须另定义 QM 区域、截断/封端和电荷/自旋，不能把几何筛选选择直接当成化学截断操作。

### 距离模式

设两个所选原子集合为 A 和 B，先按拓扑将分子还原为连续结构，再对候选镜像比较：

- `selected_min_distance`：min |r_a−r_b|，a∈A、b∈B。表示有限原子集合的接触距离，不称无限平面的数学距离。
- `selected_center_distance`：两组原子的几何中心或质量中心距离，配置必须指定中心定义。
- `plane_geometry`：由所选原子最小二乘拟合平面，报告法向夹角、层间距离、横向错位及非平面残差；通过明确的组合阈值筛选。

无限平面相交时数学距离为零；近乎平行时只看垂直距离也可能选中横向很远的分子。因此层间距模式需要横向范围/投影重叠判据。对非平行的面，不伪装存在唯一的“层间距”：可报告中心连线在两个法向的投影并结合夹角规则。规则的具体阈值由输入配置给出。

### PBC 和去重

- 支持正交与一般三斜晶胞；长分子/聚合物用键连接还原，不能只把所有原子相对第一个原子做最近镜像。
- 候选对身份包含 `(molecule_i, molecule_j, image[3])`。将反向等价对规范化，保留不同的周期通道。
- 截断范围包含多个镜像时显式枚举；是否包含分子与非零镜像自身的通道可配置，零镜像自身排除。
- 输出原始 atom ID、所选核心原子、完整 QM 原子映射、整数镜像、位移与每个几何指标。导出的 dimer 应能回溯到原始帧。
- 使用邻居搜索先粗筛，再精算共轭区域；提取本身优先保证几何正确，不先把所有距离判断塞进 GPU。

## 5. 转移积分：按 dimer 的冻结 MD 几何计算

建议首个量化适配器为 PySCF CPU＋GPU4PySCF GPU，方法接口与任务调度分离；外部 Gaussian/其他后端作为独立适配器。实际支持矩阵需逐项验证后发布。

电子/空穴对应的片段轨道、投影和正交化方法应显式选择。保存原始/有效耦合、轨道/重叠信息、AO/片段映射、计算方法和自洽收敛状态；不能用任意二聚体 HOMO/HOMO−1 或 LUMO/LUMO+1 分裂直接代表所有 V。

耦合计算使用提取的 MD 几何，不默认先优化 dimer，否则会改变原帧所代表的形貌。QM 区为两个完整分子/已定义片段；MM 区中排除这两个 QM 分子的对应经典电荷。单体轨道参考与二聚体 Hamiltonian 的 embedding/基组约定必须一致。

近简并轨道、强链内耦合或共价跨片段边界需相应的多轨道/投影方案，不能无提示按一个轨道硬套。CPU/GPU 比较耦合时需处理轨道相位；hopping 中比较 |V| 或 |V|²，保存相位约定供后续更一般理论使用。

## 6. 重组能：位点环境下的中性/带电势能面

重组能通常是各电子活性分子/片段在环境中的参数，不必为每个 dimer 重复优化同一个位点。对于不等价环境保存位点各自的结果；只有明确选择统一分子参数近似时才跨位点复用。

对选定环境和相容的电荷/自旋状态，计算两个优化构型 R0、Rq 及四个能量：

```text
E0(R0)    中性优化构型上的中性能量
Eq(R0)    中性构型上的带电能量
Eq(Rq)    带电优化构型上的带电能量
E0(Rq)    带电构型上的中性能量
λ = [Eq(R0) − Eq(Rq)] + [E0(Rq) − E0(R0)]
```

分别对 q=+1（空穴）与 q=−1（电子）处理，记录两项松弛能，保留四点能量和梯度收敛证据。MD 瞬时结构只是优化起点，不能直接冒充中性平衡构型。约束与嵌入环境需在四点计算中保持规定的一致性。

### QM/MM 层级必须明确

[PySCF 的电子嵌入](https://pyscf.org/user/qmmm.html)将 MM 电荷加入 QM Hamiltonian，但本身不包含 MM 自身能量、QM–MM 范德华等其他相互作用。

- **固定电荷静电嵌入**：适合能量/耦合和明确标注的嵌入近似。几何优化若缺少 QM–MM 短程排斥，可能产生不合理结构；不能把这一实现标签当成完整 QM/MM。
- **固定 MM 环境的完整选定 QM/MM 势能**：QM 能量/梯度加相容的 QM–MM 非静电/边界项；固定环境用于控制计算和保存 MD 形貌。此时四点式给出该固定环境条件下的重组参数，不自动包含 MM 核坐标松弛的外球重组能。
- **可松弛/可极化环境**：环境自由度、极化和初末态定义需要单独的物理方案及更完整力场；不能靠把 MM 原子取消冻结就声称已经得到无歧义的 λ_total。

推荐把完整能量分解写进适配器：E_QM(embedding)+E_MM+E_QM/MM,non-electrostatic+E_boundary，避免再叠加已经被 embedding 计入的经典静电。跨共价边界需封端/键处理。可评估 OpenMM 作为经典能量/力提供者或 CP2K 等完整 QM/MM 后端；GROMACS/LAMMPS 不同力场样式不保证均可无损转成同一 MM 引擎。

冻结环境半径、周期长程电势、总电荷和极化处理均须收敛检查。静态点电荷截取不等于完整周期 QM/MM；GPU4PySCF 提供 periodic qmmm 示例，但其与所选泛函、开壳层、梯度、优化器组合必须另外验证。

### 已确认的首个验证模式：固定 MM 坐标

本项由用户明确选择，不再作为待确认的环境自由度选项。首个案例将 MM 原子坐标保持为输入帧的值，优化变量只包含选定 QM 分子的坐标。QM 区仍需包含适用的 QM–MM 静电及非静电相互作用；冻结坐标不会使这些相互作用消失。是否使用可极化 MM 模型属于另外的模型选择，不能由“固定周围分子”推断已选定。

四点任务共享一个不可变的环境快照：MM 原子映射、坐标、适用的电荷/力场参数、周期/截断约定和边界定义均记录在任务来源中。R0 与 Rq 只表示 QM 坐标。中性与带电优化分别产生检查点；交叉单点读取相应优化几何，不再次优化，也不改变 MM 快照。计算方法、基组、网格及收敛设置按明确的两态方案保持一致，记录各电荷态的电子数、自旋与实际 SCF 收敛结果。

首个验收案例必须提供以下证据；这些是待执行的验收要求，尚无运行结果：

| 检查 | 要保存的证据 |
|---|---|
| 环境保持固定 | 每个优化步及四个单点使用相同 MM 坐标与映射，输出校验和；QM 原子身份没有交换或遗漏 |
| 势能与梯度一致 | 同一几何下完整势能的 QM 梯度对照有限差分；电子嵌入静电不被经典项重复计算；固定 MM 不要求其受力为零 |
| CPU/GPU 对照 | 相同 Hamiltonian、几何和数值设置的单点能量与 QM 梯度；独立优化的几何、最终梯度和 λ 对照；明确数值容差与失败状态 |
| 四点来源可追溯 | E0(R0)、Eq(R0)、Eq(Rq)、E0(Rq)、两项松弛能、优化/SCF 状态与环境快照引用；保留原始 Hartree 和换算记录 |
| 结果标签准确 | 标注“固定 MM 环境下的四点重组能”；不称包含 MM 结构松弛的总重组能；不直接将单个位点两项松弛能之和作为任意异质分子对的 λ |
| 性能可解释 | 记录优化迭代次数、SCF 次数、显存峰值和含初始化/传输的总墙钟时间，避免由不同收敛工作量得出错误加速比 |

已确认的环境自由度并未指定具体力场、泛函、基组或嵌入半径。这些参数仍需随实际验证输入给出，并进入缓存 key 和报告；不能由软件静默猜测。

## 7. GPU 量化后端

GPU 加速范围明确包含 **QM/MM**，并非仅限真空中的单分子或 dimer。拟议组合是 GPU4PySCF 计算受支持的嵌入 QM 能量与梯度，兼容的 MM 引擎计算经典项；例如 OpenMM 的 CUDA 平台可加速其支持的 MM 力场。二者之间的能量/力耦合、静电去重和边界处理仍需在 cube 中实现并验证，不能将安装两个软件视为已经获得完整 QM/MM 后端。

后端选择保留两条可比较的路线：

| 路线 | 对 cube 的价值 | 必须核验的边界 |
|---|---|---|
| GPU4PySCF＋兼容 MM 引擎 | Python 接口便于取得轨道、投影耦合以及编排四点能量 | cube 需实现并校验完整耦合；不同力场、周期电势、开壳层与梯度组合不能据独立组件功能推定均可用 |
| CP2K 独立任务适配器 | 复用其已有 QM/MM 模型，作为完整计算引擎候选 | 实际方法、GPU 构建、输入力场和参数定义逐项核验；不能直接把两种引擎的不同 Hamiltonian 结果当成同一数值基准 |

推荐先通过前一路线明确轨道/能量/力接口，并保留后一适配器的接口位置。选定力场不能表达时应明确拒绝或由用户选择经过说明的映射，不能因成功读取 GROMACS/LAMMPS 坐标就声称完成了该力场的 QM/MM。上游依据：[OpenMM 的 GROMACS 输入](https://docs.openmm.org/latest/userguide/application/02_running_sims.html#using-gromacs-files)、[CUDA 平台](https://docs.openmm.org/latest/userguide/library/04_platform_specifics.html#cuda-platform)、[CP2K QM/MM 模型](https://manual.cp2k.org/trunk/CP2K_INPUT/FORCE_EVAL/QMMM.html)。这些是设计建议，并非本项目已运行的后端。

已查阅 PySCF 官方 GPU/QM-MM 文档，以及固定版本 GPU4PySCF 的嵌入、梯度和优化示例。来源及校验和见 [gpu-qmmm-sources.json](../research/gpu-qmmm-sources.json)。没有安装并运行这些量化组件，不能据源码示例声称本机已完成 GPU QM/MM。

拟议任务层：`single_point`、`energy_gradient`、`optimize`、`fragment_coupling`。其中 coupling 由定义明确的量化结果组合，不把它误称为上游现成的通用接口。按方法/电荷自旋/embedding/梯度支持查询能力，不支持的组合在提交任务前拒绝。

GPU 优先用于 DFT/HF 的受支持计算、能量梯度和优化中的电子结构步骤；预处理、优化器控制和小矩阵后处理可在 CPU 上。实际 GPU 覆盖由调用轨迹和计时记录验证。

显存与调度：单 GPU 默认按任务排队；支持多 GPU 分配独立 dimer/位点任务；缓存 key 包含几何、环境、电荷/自旋、基组、泛函/网格、收敛和程序版本。复用同一物理任务的检查点与单体参考，不只按分子编号缓存。GPU OOM/SCF 失败/优化失败分别记录；GPU 请求默认不静默转 CPU，不自行降低基组或换泛函。

本机只读宿主机查询（2026-11-05）：GTX 1650 Max-Q，4096 MiB 显存，驱动 615.71.09；本地 nvcc 显示 CUDA 13.4。受限环境直接 NVML 查询失败，宿主机查询成功；以实际量化运行探测为最终可用性证据。当前 Python 未发现 PySCF/GPU4PySCF/CuPy。4 GB 显存不能作为所有 dimer 均可计算的保证，也不能据上游大 GPU 性能数字承诺本机加速倍数。

## 8. GPU KMC 后端

GPU KMC 是独立需求，不由 GPU 量化后端自动获得。建议第一条路径是同一速率网络上的大量独立轨迹并行，单条轨迹内部按 CTMC 顺序推进。每条轨迹独立时间、位点、累计位移与随机流；轨迹终止条件与观测网格保持物理意义。

- 将 CSR 邻接/速率放入设备内存，多个轨迹共享；对静态率缓存位点总率和累计率。
- CPU 四语言后端仍保留。GPU 先支持明确的材料图模型与数值数组，不声称任意 Python 回调可自动在 GPU 执行。
- 使用独立的 counter/stream 分配，避免所有线程复用相同种子流；任务批次和设备调度不应重新定义物理采样。
- 对不同轨迹步数差异、warp 分支、显存、观测输出做批次/流式统计设计，不用跳过等待区间或统一物理时间步换取速度。
- 指定相同随机数序列的小测试核对 CPU/GPU 事件与截止时间；正式 GPU 随机源与 CPU 不同则比较解析量、确定性解及统计分布，不能要求同 seed 逐轨迹一致。
- 记录主机到设备、kernel、回传、分析和总墙钟时间；GPU 计时需要同步，避免将异步提交耗时当计算耗时。不能未经基准承诺 GPU 总比 CPU 快。

首个实现可用 CuPy 原型验证批轨迹与显存布局，再按测量决定是否采用独立 CUDA/C++ 核。四语言前端可调用同一 GPU 后端协议，不需要四份互不相干的 CUDA 实现。具体框架尚未锁定；用户没有撤销四语言 CPU 核心要求。

用户已确定首版先验证独立单载流子轨迹，因此首版 GPU 路线采用独立轨迹批处理。多条轨迹不产生共享占据，也不加入轨迹之间的载流子相互作用。后续若支持有限浓度，一个轨迹内的多粒子状态/允许事件/库仑速率须一致更新；独立单载流子轨迹的 GPU 批处理不能替代多粒子物理。具体公共状态边界见[构建讨论中的后端契约](2026-11-05-cube-construction-discussion.md#公共后端契约)。

## 9. 更新后的实现顺序与验证

此前建议“先导入参数”的 A 路线保留为内部开发/验证入口；用户可用的完整目标现在包含 MD 提取、参数生成和 GPU，不能将这些关键要求全部延到首版之外。

1. **结构与提取**：统一 GROMACS/LAMMPS 适配器、局部编号、所选共轭区、PBC 与去重。相同坐标的两种格式应提取相同分子对/镜像；测试跨界分子、倾斜盒、侧链干扰、横向远但层间近的假接触、多个镜像和非共价/共价片段边界。
2. **量化垂直原型**：小分子对、明确定义的 MM 环境；CPU 单点/梯度作为参考，再验证 GPU；构建投影耦合和四点重组能任务。优化梯度需对有限差分，完整势能能量/力不重复计数；电子/空穴、自旋与不支持组合分别验收。
3. **任务工作流**：批量 dimer 与位点任务、缓存、检查点、失败恢复、GPU 显存调度、参数来源报告。检查环境半径与量化精度收敛。
4. **输运闭环**：同一套参数生成率、四语言 CPU 参考与 GPU KMC，扩散/漂移/迁移率统计和数值基准；确认完整物理时间观测一致。

验收不是只展示 GPU utilization：应展示从一帧输入到 dimer 清单、量化原始能量/耦合、速率和最终输运报告的完整来源链，以及 CPU/GPU 误差和包含数据传输的性能测量。

## 10. 后续运行配置与验证输入

- 共轭区域的具体距离定义与阈值；接口保留各几何指标，实际任务必须显式指定筛选规则，不把此前的推荐当作用户已经选择的默认值。
- 首版已确定独立单载流子轨迹。初态分布、温度/场、观测时间与轨迹数随运行配置给出，并做相应收敛检查。
- 首个 QM/MM 验证的环境坐标已确定固定；具体势能模型、力场支持列表、QM 方法与环境范围仍需随实际输入确定。
- 实际用于端到端验证的可读 MD 帧、拓扑/电荷/力场与原子选择。原 SSD 路径本次未挂载，不把已保存派生参数当成完整原始结构。

这些输入尚未提供不妨碍本轮架构讨论形成方案，但会阻止实际案例计算；必须在启动相应任务前补齐和校验。本文交付的是构建方案与验收要求，不是已实现或已验证完整 MD→GPU QM/MM→GPU KMC 流程的声明。
