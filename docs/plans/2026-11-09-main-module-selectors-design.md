# 主模块内部选择子任务

用户指定 `$charge-carrier` 内增加 `get_dimers_monomers`、`one-mol`、`two-mol`、`reorganization-energy`、`kmc` 的 0/1 选择。公共框架从每个 CalculationType 的模块定义派生可接受字段，不把这些字段写成仅载流子可用的特殊解析。kmc 子模块及科学实现先在载流子分支注册和开发。

主模块 `do=0` 不产生其调用请求；`do=1` 时内部字段为 1 才请求对应子模块，为 0 不调用它。省略字段保留原自动调度，以兼容旧文件。子模块自身 `do=1` 仍是独立请求，主模块内的 0 不会取消这个独立请求。子模块自身 `do=0` 保持禁用语义；完整主流程显式请求 1 而子模块明确禁用时，执行预检报告配置冲突，不静默丢失步骤。

完整主流程显式请求某步但未提供设置段时，执行预检要求提供参数。跳过前处理时，下游须有明确已有输入。隐式数据依赖不能绕过主模块的 0；独立子模块请求的合法依赖仍由独立路径处理。同一模块由多个主模块或独立开关请求时，只运行一次。

所有内部开关在主模块关闭时仍检查严格的 0/1 和拼写，但不启动科学计算。计划中 `entry_points.*.module_selection` 记录自动调用选择。测试包括过滤、独立开关不受主选择限制、无效值、缺少配置和显式冲突。
