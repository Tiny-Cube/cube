# 主模块编排与子模块独立执行

用户用结构图明确：charge-carrier、exciton、surface-hopping 为主模块，负责按需组织基础功能；get_dimers_monomers、one-mol、two-mol、reorganization-energy 及后续子模块可被多个主模块复用，也能独立运行。用户进一步选择在子模块添加 `do`，不要求命令行独立入口。

## 开关契约

主模块的 `do=1` 请求完整计算，`do=0` 不请求该主模块。子模块 `do=1` 是独立执行请求，不依赖任何主模块或其自动调度列表；`do=0` 明确禁用该子模块，主流程不能隐式重新启用。子模块省略 `do` 表示自动调度，用于兼容已有控制文件。没有任何主模块段的旧文件仍保留直接模块执行，显式 `do=0` 同样有效。

普通运行的任务集合是主模块所需任务与子模块独立请求的并集，按已有数据依赖排序，同一模块只执行一次。`--only` 筛选主模块或模块子集，不覆盖显式关闭的模块。主模块的 modules 声明表示其自动组织的功能，不是子模块独立执行的权限表。

独立量化请求优先使用自身 `input`/`xyz`。无显式数据源时，可添加控制文件中的自动提取模块；若提取 `do=0` 则要求提供已有数据或开启提取，并在科学计算前报错。独立 two-mol 仍可内部计算必要的片段单点，这不等同于执行整个 one-mol 批处理。完整主模块有额外必需模块时，由相应主模块的预检检查，不允许把准备成功当作最终输运完成。

## 解析、执行与报告

解析器首先验证所有 `do` 为严格的 0/1，再只验证活动模块的数据路径与物理配置；关闭模块的未知字段、重复字段等语法错误仍拒绝。主模块全关且没有独立请求时不启动任务；主模块全关而 one-mol do=1 时只运行 one-mol 及其数据依赖。

主流程与独立调用共用调度器、参数检查、SCF/量化实现、结果写入与续算机制，不建立另一套科学实现。报告保持兼容字段 `module_owners`，其中 `standalone` 表示用户的直接请求，主模块名称表示主流程调用；新增 `requested_modules` 与 `module_switches` 解释任务来源，自动状态记为 null。独立任务不会启动主模块求解器。

## 分支与验证

公共变更先进入 `feat/calculation-entries`，然后合并到三个计算分支。surface-hopping 分支的专用 dynamics 子模块同样支持 do；其专用代码不反向合并进其他分支。

验证包括：全关主模块的真实 H2 单点与成功续算、显式禁用优先、独立请求与主流程合并去重、跳过无关数据、依赖添加/禁用报错、旧输入兼容、严格开关检查，以及原有完整回归。不启动真实材料的大规模量化或远端 GPU 作业。
